# Detailed Prompt: Fix Stop List ↔ Map Synchronization Bug

I am developing a production-grade real-time college bus tracking system called **NextStop JGI** using:

* React 18
* TypeScript
* Node.js
* Socket.io
* MapLibre GL JS
* Turf.js
* OSRM Route Matching
* Bottom Sheet containing route stops

## Current Problem

There is a synchronization bug between the **route stop list** and the **interactive map**.

### Current Behavior

**Case 1 (Incorrect)**

When the user clicks a stop inside the route list:

```
Student clicks
Muradeshwar Ceramics

↓

The map flies to an incorrect location.

↓

Sometimes it points to another stop.

↓

Sometimes it points somewhere random on the route.
```

---

**Case 2 (Correct)**

When the user clicks the actual stop marker on the map:

```
User clicks marker

↓

Correct stop popup opens

↓

Correct stop is highlighted

↓

Bottom sheet stays synchronized.
```

This means:

✅ Map → List synchronization works.

❌ List → Map synchronization is broken.

---

## Expected Behaviour

The synchronization must work identically in both directions.

### Clicking a stop in the list should:

1. Locate the exact stop object
2. Fly the map smoothly to that stop
3. Highlight the correct marker
4. Open the marker popup
5. Highlight the selected stop in the list
6. Scroll the stop into view if needed

---

### Clicking a marker should:

1. Select the same stop object
2. Highlight the stop card
3. Keep both map and list synchronized
4. Never produce mismatched selections

---

# Important Requirement

Do NOT synchronize using:

* array index
* rendered order
* filtered index
* sorted index

Everything must synchronize using a unique stop identifier.

Example:

```
stop.id
```

or

```
stop.stopId
```

Every interaction must reference the exact same stop object.

---

# Things I want you to investigate

Before writing code, inspect the entire stop synchronization flow.

Look for:

## 1. Array Index Mismatch

Check whether:

```
stopList[index]
```

is mapped to

```
marker[index]
```

instead of matching by stop ID.

If found, replace with ID-based lookup.

---

## 2. Different Stop Arrays

Verify whether the map and list use different arrays.

Example:

```
List

stops[]

Map

route.geometry[]
```

or

```
displayStops[]
```

vs

```
routeStops[]
```

Both components must use the same source of truth.

---

## 3. Latitude / Longitude Issues

Verify coordinates.

MapLibre expects:

```
[longitude, latitude]
```

Never:

```
[latitude, longitude]
```

Also verify that no coordinate conversion swaps values.

---

## 4. Route Geometry vs Stop Coordinates

Ensure clicking a stop does NOT use

```
route.geometry[index]
```

Instead it must use

```
stop.latitude
stop.longitude
```

Only actual stop coordinates should be used for centering.

---

## 5. Marker Lookup

Markers must be stored like:

```
Map<
 stopId,
 Marker
>
```

instead of

```
Marker[]
```

Then retrieve:

```
marker = markerMap.get(stop.id)
```

instead of

```
markers[index]
```

---

## 6. Popup Synchronization

When selecting a stop:

Automatically:

* flyTo()
* openPopup()
* highlight marker
* update selected stop state

---

## 7. Single Source of Truth

There must be only one selected stop state.

Example:

```
selectedStopId
```

NOT

```
selectedIndex
selectedMarker
activeStop
clickedStop
```

Use:

```
selectedStopId

↓

derive everything else
```
